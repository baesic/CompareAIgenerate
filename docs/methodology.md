# Methodology

이 문서는 `CompareAIgenerate` 프로젝트의 실험 설계와 평가 기준을 설명합니다.

## 1. 실험 목적

이 프로젝트는 하나의 원안이 서로 다른 AI 모델을 거치며 어떤 블로그 글로 재구성되는지, 그리고 다시 AI 평가 모델이 그 결과물을 어떤 기준으로 판단하는지 비교합니다.

분석 초점은 두 가지입니다.

- 생성 품질: 원안의 문제의식, 문체, 논리, 게시 적합성이 얼마나 잘 재구성되었는가
- 평가 품질: 평가 모델이 점수와 설명을 얼마나 일관적이고 활용 가능하게 제시했는가

## 2. 데이터 흐름

| 단계 | 입력 | 처리 | 출력 |
| --- | --- | --- | --- |
| 원안 작성 | baesic의 초안 | 문제의식과 표현을 그대로 보존 | 원안 |
| 생성 | 원안 | 세 모델에 블로그 글 생성을 요청 | A안, B안, C안 |
| 평가 | 원안과 세 생성안 | 세 모델에 비교 평가를 요청 | 모델별 평가표 |
| 정규화 | 서로 다른 평가표 | 10점 기준으로 비교 가능하게 정리 | 통합 비교표 |
| 메타 평가 | 평가 결과 전체 | 설명력, 활용성, 균형감 비교 | 최종 리포트 |

## 3. 생성안 해석 기준

| 생성안 | 해석 축 | 주요 관찰 포인트 |
| --- | --- | --- |
| A안 | 핵심 요약형 | 제목, 소제목, 짧은 결론 중심의 전달력 |
| B안 | 균형형 게시본 | 원안 취지 보존, 사실 보정, 독자 친화성 |
| C안 | 심층 칼럼형 | 기술 해설, 비유 확장, 인상적인 마무리 |

## 4. 평가 모델 품질 기준

평가 모델 자체의 품질은 다음 5개 기준으로 다시 비교했습니다.

| 기준 | 의미 |
| --- | --- |
| 구조 명확성 | 평가표와 설명이 빠르게 이해되는가 |
| 균형감 | 원안 보존과 게시 적합성 사이의 교환 관계를 공정하게 보는가 |
| 실행 가능성 | 최종 게시본 선택이나 수정 방향에 바로 활용할 수 있는가 |
| 뉘앙스 분석력 | 화자의 어조, 문체 변화, 손실된 표현을 짚는가 |
| 설득력 | 점수와 설명이 서로 일관되고 납득 가능한가 |

## 5. 정규화 방식

각 평가 모델은 서로 다른 배점 체계를 사용했습니다.

- Gemini 3.1 Pro: 10점 평균
- ChatGPT 5.5: 80점 총점과 10점 평균
- Opus 4.6: 100점 총점

비교표에서는 모두 10점 기준으로 볼 수 있게 정리했습니다. 예를 들어 Opus 4.6의 85점은 8.5점으로 표시합니다.

## 6. 현재 결론

생성안 기준으로는 `B안`이 가장 안정적입니다. ChatGPT 5.5와 Opus 4.6 평가에서 모두 1순위였고, 실제 게시용 글로 쓰기 좋은 균형을 보여줍니다.

평가 모델 기준으로는 `Opus 4.6`의 분석이 가장 정밀합니다. 특히 원안의 생생한 표현이 다듬어지는 과정에서 무엇이 보존되고 무엇이 약해졌는지를 가장 잘 설명합니다.

실무 활용 관점에서는 다음과 같이 나눌 수 있습니다.

| 목적 | 추천 |
| --- | --- |
| 빠른 요약과 공유 | Gemini 3.1 Pro |
| 게시용 초안 선택 | ChatGPT 5.5 |
| 정밀한 문체 분석 | Opus 4.6 |

## 7. 한계

이 프로젝트는 하나의 원안과 한 번의 비교 실험에 기반합니다. 따라서 모델의 일반적인 우열을 단정하기보다는, 특정 글쓰기 과제에서 드러난 평가 성향과 활용 가능성을 분석한 사례로 보는 것이 적절합니다.

모델 버전, 프롬프트 조건, 생성 시점이 바뀌면 결과는 달라질 수 있습니다. 재현성을 높이려면 추후 실험마다 프롬프트, 실행 날짜, 모델 버전, 원문 전체를 함께 기록하는 방식이 필요합니다.
